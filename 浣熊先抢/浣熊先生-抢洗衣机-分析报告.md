# 浣熊先生洗衣 · 自动抢洗衣机 可行性分析报告

> 分析时间：2026-02 · 数据来源：开源项目 [Lide4Code/Hxxy](https://github.com/Lide4Code/Hxxy)（华南农业大学同供应商实测）、[浣熊先生官网](https://www.mrrac.com/)、各高校学生评测（colleges.chat）

---

## 1. 平台是什么

**浣熊先生（Mr. Raccoon，mrrac.com）**：一家"一人一桶"共享洗衣服务商，覆盖国内多所高校
（华南农业大学、东北电力大学、青岛科技大学、山西科技大学、广东水利电力职院等）。

- 使用入口：**微信小程序**（华农案例 appid：`wxf3d088fc4d192e93`）
- 使用流程：小程序选洗衣机 → 绑定**自己的洗衣桶编号**（波轮机需要自购内桶，滚筒免桶）→ 支付 → 开洗
- 4 元/次左右，高峰期（晚间）可用机器少、**窗口期以秒计**——这就是"抢"的需求来源

## 2. 接口分析（核心结论）

好消息：**该后端目前无签名、无加密参数**，普通 HTTP 请求即可重放，鉴权只靠一个请求头 `token`。

- API Host：`https://hxxs.mrrac.com`（子域名疑似按校区划分，**你学校的子域名要抓包确认**）
- 通用请求头：`token`（登录凭证，URL-encoded 长串）、`from-agent: wxmini`、`api-version: 1.0.0`、`Content-Type: application/json`

### 2.1 核心端点（三件套）

| 功能 | 方法 | 路径 | 关键参数 |
|---|---|---|---|
| 拉取洗衣机列表 | GET | `/home/loadHomeWashList?category=1` | 仅需 token |
| **下单（抢）** | POST | `/order/saveDorOrder` | `bucketNumber`（桶编号）、`channel`（洗衣房渠道号）、`washId`（机器ID）、`washTypeCode`（如 `QUICK_WASH`） |
| 切换洗衣房/宿舍 | POST | `/user/saveUserSelf?obj={...}` | dormitoryId / floorId / dormitoryNo 等 |

### 2.2 洗衣机数据结构（实测 JSON 样例字段）

```json
{
  "washId": 8050,               // 下单用的机器 ID
  "washroomNumber": 9,          // 几号机
  "washRoomId": 1799,           // 所属洗衣房（channel 映射用）
  "state": 1,                   // 1=可用 0=维护中 3=洗涤中 4=漂洗中
  "stateName": "可用",
  "remainTime": 0,              // 剩余分钟数（洗完即释放）
  "washAllInfo": "2号楼1层-9号机",
  "washerConfig": "10X",
  "faultState": 0
}
```

### 2.3 下单后

- **下单成功 ≠ 支付成功**：抢到后需回小程序完成微信支付，超时可能释放。脚本不碰支付环节。

## 3. 抢购策略（参考项目做法 + 可优化点）

参考项目策略：
1. 常驻轮询洗衣机列表，发现 `stateName == "可用"` → 立即对目标机器 `saveDorOrder`
2. 无可用机时盯 `min(remainTime)`：>3min 慢轮询（10s）、≤3min 加速（2s）、≤1min 进入极速模式（0.2~1s）
3. **熔断**：同一台机器连续失败 5 次暂时跳过（防止死刷坏机器 / 触发风控）

可以做得更好的：
- **本地倒计时外推**：拿到 remainTime 后按本地时钟递减估算，减少 API 调用次数
- **并发下单**：最后 1 分钟对 2~3 台候选机器并发尝试，提高命中率
- **成功通知**：Server酱 / PushPlus / 邮件推送"抢到了，快去付款"
- **token 失效检测**：接口返回未登录时自动提醒重新抓包，而不是傻刷

## 4. 上手前你需要准备的 4 样东西

| # | 东西 | 怎么拿 |
|---|---|---|
| 1 | `token` | **抓包**。Windows：PC 版微信开小程序 + Charles（SOCKS + SSL Proxying，`*:*`）→ 可再转 Burp 分析；Fiddler 对微信小程序经常抓不到（SOCKS/证书问题）。Android：HttpCanary / Fiddler+证书。抓任意一个业务请求，复制请求头里的 token |
| 2 | `bucketNumber` 桶编号 | 小程序"我的洗衣桶"页面直接看 |
| 3 | 你学校的 API 子域名 | 抓包看请求 Host（华农是 `hxxs.mrrac.com`，你校可能不同） |
| 4 | `channel` / `washTypeCode` | 在小程序里**正常手动下单一次**并抓包，照抄这两个参数 |

## 5. 风险与注意事项

- **合规**：仅供个人自用、抢到自己要用的那台为止；不要高频 7×24 轮询、不要做多桶/黄牛化使用——容易被封 token 或被运营商标记。
- **生命周期**：华农小五山后来换了供应商、脚本失效，但作者确认"方法和接口不变"。供应商随时可能加签名/风控，代码要留好适配层。
- **礼仪**：抢到请尽快支付；不用时取消占位，别占着机器影响同学。
- **token 有效期未知**（数天~数周量级），脚本必须做失效检测。

## 6. 建议的实现方案（下一步三选一）

| 方案 | 形态 | 特点 |
|---|---|---|
| A | 单文件 CLI 脚本（`config.json` + 抢购循环 + 推送） | 最快见效，一晚搞定 |
| B | 本地 Web 控制台（Flask + 网页，仿 Hxxy 增强） | 实时状态表、一键抢/取消、配置持久化，最好用 |
| C | 常驻后台守护 + 微信推送 | 适合"睡前预约、半夜自动抢" |

**推荐路线：A 起步验证接口 → 加 UI 升级成 B；通知能力两者共用。**
